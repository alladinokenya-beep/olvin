A friendly, hands-on guide

Your first Git commit with Git Bash

Learn how to save a snapshot of your project, check your work, and send it to GitHub—one clear command at a time.

Beginner friendly · Windows · No experience needed

The quick version

Open Git Bash in your project folder. Then use these commands to prepare and make a commit:

git status
git add .
git commit -m "Describe your change"

A commit saves your changes in Git on your computer. It does not automatically upload them to GitHub. To upload, you normally use git push afterward.

First, what are Git and Git Bash?

Git

Git keeps a history of changes to your files. You can save checkpoints, compare versions, and work safely on a project over time.

Git Bash

Git Bash is a command window installed with Git for Windows. You type Git commands there to manage your project.

Three places to know

  1. Working folder: the files you are editing right now.
  2. Staging area: the changes you have selected for the next commit.
  3. Repository history: the commits Git has already saved.

Think of staging as putting items into a box, and committing as sealing and labeling that box.

1. Install Git and open Git Bash

If Git is not installed yet, install Git for Windows. Search your Start menu for Git Bash to open it.

Move into your project folder using cd. For example, if your project is in Documents:

cd ~/Documents/my-first-project

Replace my-first-project with the actual folder name. To see the files and folders where you are, type:

pwd
ls

Tip: In File Explorer, you can often right-click inside your project folder and choose Open Git Bash here.

2. Set your name and email (one-time setup)

Git records who made each commit. Set the name and email you want attached to your commits:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Use your own name and email instead of the examples. The --global option applies these settings to your Git projects on this computer.

Check what Git saved:

git config --global --list

3. Make your first commit

  1. Check the folder. Make sure Git Bash is open in the project folder. Run pwd to see your current location.
  2. Check the changes. See which files are new or have been edited:
git status
  1. Stage the files you want to save. To stage all changes in this folder, run:
git add .

The dot means “include changes under the current folder.” To stage just one file, use its name instead, for example git add index.html.

  1. Check staging. Run git status again. Staged changes are usually shown in green. Review the list before committing.
  2. Save the commit. Write a short message that explains what you changed:
git commit -m "Add welcome page"

The words inside the quotation marks are your commit message. Make it specific, such as Fix navigation links or Add contact form.

  1. Confirm it worked. Git prints a confirmation. You can also check your recent commits with:
git log --oneline

Your everyday commit routine

After you edit files, repeat this simple cycle:

git status
git add index.html
git status
git commit -m "Update homepage text"

Replace index.html and the message with the file and change you actually made. If you want to stage every changed file, use git add . instead.

Good habit: Use git status before staging and before committing. It helps you catch files you did not mean to include.

What makes a useful commit message?

  • Keep it short but clear.
  • Describe the change, not just “stuff” or “updates.”
  • Make each commit about a sensible small set of changes.

Commit versus upload to GitHub

A commit is saved in your local repository. Pushing sends commits to a remote repository, such as GitHub.

If you already cloned a GitHub repository

After committing, send your commit to the current branch on GitHub with:

git push

If this is a new local project

Create an empty repository on GitHub first. GitHub will show the correct remote URL and setup instructions. Add that URL as your remote, using the URL GitHub provides:

git remote add origin https://github.com/YOUR-USERNAME/YOUR-REPOSITORY.git

Then check the branch name and push it (many new repositories use main):

git branch -M main
git push -u origin main

Important: Replace the sample remote URL with your own repository URL. Do not copy the placeholder literally. GitHub may ask you to sign in or authorize Git.

Useful Git commands

CommandWhat it does
git statusShows changed, staged, and untracked files.
git add filenameStages one file for the next commit.
git add .Stages changes in the current folder and its subfolders.
git diffShows edits that have not been staged yet.
git diff --stagedShows edits that are staged for the next commit.
git commit -m "message"Saves the staged changes as a commit.
git log --onelineShows a compact list of recent commits.
git pullDownloads and integrates changes from the remote repository.
git pushUploads your commits to the remote repository.

Common beginner problems

“Please tell me who you are”

Set your name and email using the commands in the one-time setup section, then try the commit again.

“Nothing to commit”

Git may have no new changes to save, or you may be in the wrong folder. Run pwd and git status to check.

“Untracked files”

These are new files Git has not started tracking yet. Stage the file with git add filename, then commit it.

“The current branch has no upstream branch”

For a first push of a branch, Git may suggest a command such as git push --set-upstream origin main. Follow the suggested branch name shown in your terminal.

I staged the wrong file

To remove a file from staging without deleting it, use:

git restore --staged filename

Then run git status and stage the correct files.

Be careful: Avoid commands that delete files or rewrite commit history unless you understand what they do. If you are unsure, check git status first and ask for help before running a destructive command.

Before you finish

  • ☐ I opened Git Bash in the correct project folder.
  • ☐ I checked my changes with git status.
  • ☐ I staged only the files I want to save.
  • ☐ My commit message explains what I changed.
  • ☐ I remembered that committing is local; pushing uploads to GitHub.

You are ready! Keep practicing with small changes, and use git status whenever you want to know what Git sees.
